How Build Prompts Are Written
(Read at about 130 words a minute. UK English.)

Rory is thirteen. He was watching his dad plan a change to Trimtable for Juno Platt's salon, The Tidy Paw. Rory had an idea to save time: ask the AI builder to add appointment reminders and a new price list in one request. One message, two jobs, done. His dad shook his head. In this stage every request costs credits, he said, and if a two-job request goes wrong, nobody can tell which half broke, or how to undo just that half. That was the moment it made sense. One prompt, one job, one test, one way back.

This is Stage 6, called Prompts. It happens in the room called Reactor, and it is the only paid stage in the whole factory. Every earlier stage is free planning and free building by hand. Here, the factory sends written instructions, called prompts, to the build platform's AI builder, and each answer, called a turn, spends credits. Because money is spent, the rules get stricter. Every prompt is prepared, checked and tested on paper first, and the factory owner gives the go word before each one is sent. Nothing is sent on a hunch.

The first rule is one goal, one surface. A surface is one part of the app that a person sees or uses, such as the booking screen or the price list. The template line puts it simply: an and means two prompts. Add reminders and change prices is two prompts, not one. Keeping prompts small means a failure is easy to spot and cheap to undo. There is a second split too. Tables and code never go in the same prompt. Tables are made by hand, for free, and the prompt is told not to change them.

Every prompt is built from fixed blocks. A context block lists exactly which files the builder may read, and nothing else. A tables block says the tables were made by hand and must not be changed. And for any app with more than one brand, a walls block goes into every prompt for the life of the app. It states the app's classification, how a row belongs to a tenant, that the app must fail closed, and one line: if a change would weaken this, stop. Fail closed means that when in doubt, the app refuses access.

Each prompt also carries its own test. Where the app has brands, the test covers both walls: the brand wall, where Brand B cannot see Brand A, and the member wall, where one member cannot see another member's rows. The tests are run from outside the app by the factory's agents. The builder is never asked to build test panels or check its own work inside its turn. That would be a bit like marking your own homework. An outside test, run by someone else after the turn, is the only result that counts.

Each paid prompt also carries a written rollback step. Rollback means going back to the last good version if a turn goes wrong. Before sending, the factory takes an export ZIP, a packed copy of every file in the app, so there is always a known good point to return to. Every prompt ends with one fixed line asking the builder, before building, to list anywhere else in the app that must change, and anything this could break. The builder reports that list first. Surprises found before building are cheap. Surprises found after building are expensive.

Before any prompt goes out, the factory writes a three-line pre-send report and adds a task to a list called Sends. Each send moves through fixed steps: draft, check, tested, the go word, sent, and verified live. The go word is a short command the factory owner types to approve one paid send. No agent can give it. Small wording or colour changes skip all of this. They go through the free visual editor instead, never through a paid prompt. Paying credits to change one word would simply be waste.

So a good build prompt is small, tested and reversible. It does one job on one surface. It carries the context block, the tables block and, for any app with brands, the walls block. It brings its own outside test for both walls, a rollback step and the what could this break question. It goes out only after the pre-send report and the owner's go word. Rory's two-job request becomes two careful prompts, each easy to check and easy to undo. Next lesson: what happens the moment a paid turn comes back.
