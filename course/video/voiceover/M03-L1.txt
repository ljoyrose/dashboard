Picking A Base
(Read at about 130 words a minute. UK English.)

Meet Rory. He had an idea for a booking desk for dog groomers, a bit like our sample app Trimtable, and it had just passed the Merit gate. He wanted the first screens working by the weekend, so he opened a blank project and started typing. By Sunday he had rebuilt a sign-in page, a menu and a cookie notice, all things he had built before, and not one part that was new. Then it clicked. If you start from a base that already works, you only build the parts that make your app different. That is Stage 2.

Stage 2 in the factory is called Base. A base is the starting app you copy before you add anything new. Stage 2 sits in the Research room, the same room as Stages 1 and 3, and it is free: no build credits are spent here. Credits are the units the build platform charges for each paid building turn. The job of this stage is short and strict. Choose a base, copy the template folder, save a backup, check for duplicates, list the bricks, and prove the base is safe. Then the Base gate opens by itself.

The first choice is remix or rebuild. To remix means to start from an existing base app that the factory already owns, kept on a shelf of bases, and change it. To rebuild means to start fresh, because no base fits. The factory records a fresh start as BESPOKE, which means made to order. A rebuild is never chosen on a whim. It has to come with the result of a dedup check that proved nothing suitable already exists. Most of the time a remix wins, because the floor of the app, meaning sign-in, menus and legal pages, is already built and tested.

Dedup is short for de-duplication, which means removing copies. The dedup check is run live on the build platform, not from memory. It asks a simple question: does something we already own do this job, or most of it? If the answer is yes, that is the base. If an earlier base was looked at and turned down, its name is written down with the reason, so nobody suggests it again next month. This one habit saves a lot of money later, because building the same thing twice costs twice, and the second copy has to be tested and looked after as well.

Next, the factory clones the template app folder. To clone means to make an exact copy. Every app gets its own folder made from the same template, so every app's papers sit in the same places. Be clear about one thing: this is a folder of documents, not the live app. The app itself is created on the build platform later, when the feature list is frozen at the Lock gate. The moment a base is chosen, an Export ZIP is taken. A ZIP is one packed file holding a full copy, so there is always a safe point to go back to.

Then comes the brick list. A brick is one reusable part, such as booking or invoices, and a kit is a named bundle of bricks that ship together. The list includes the kits, by their ids, and every brick's status is quoted word for word, never guessed. One rule from the checklist is worth remembering: never say there are no bricks for something until you have searched the kits and the design notes. The colours are settled here too. They live in one place only, as rows in the app's palette table, never typed into the code. You will meet bricks properly in the next lesson.

A base can look fine and still leak. A leak is when one person or business can see data that belongs to someone else. So the base gets a security vet, which means a careful check, using two separate test accounts. Each account signs in and tries to see the other's records. If either can, the base fails, however good it looks. This matters even more for a reseller app like Litterline, where a club such as Northvale Canine Society sits above many breeders. A copy of a leaky base copies the leak into every app built on it.

Now the gate. The Base gate sits between Stage 2 and Stage 3, and it asks one question: is the base named, and has the vet passed? It is an auto gate, which means no person has to click yes. When every Stage 2 checklist line is ticked, the engine moves the app on by itself. Compare that with Screen and Merit, where a person decides. Base can be automatic because its questions have plain answers: a name is written or it is not, and a test passed or it did not. Let us recap what makes a good base.
