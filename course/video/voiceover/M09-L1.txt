Watching A Live App Daily
(Read at about 130 words a minute. UK English.)

Isla spent weeks helping a team launch Litterline, the licence and records hub for dog breeders. On launch day she thought the hard part was over and she could move on to the next idea. Then one question kept nagging at her. If a change went wrong overnight, and one breeder could suddenly see another breeder's puppy buyers, who would notice? Nobody was sitting up watching. Her answer arrived the next morning, at twenty to seven. The factory had already checked every table by itself. Launch is not the end of the road. It is the start of a lap.

Stage 8 is Operate, and its room is called Radar. A room is simply a place on the factory floor where apps at one stage sit. Radar's tag is Watching, because watching is the main job here. A live app is serving real people, so it cannot be pulled back to an earlier stage like a draft. Instead it goes round a lap. Every fix and every new feature re-enters the road part-way, and the only way out is a gate called Retire. So Stage 8 has no gate out. It has a set of checks that run again and again.

Behind the factory sits the engine. The engine is a script, which means a small program that runs on a timer and does the same job the same way each time. Every 15 minutes it reads the task board, where each app has one card showing its stage, and writes a state file. A state file is a plain record of where every app is right now. The factory dashboard reads that file, so the picture on screen is never more than about 15 minutes old. Nobody has to update it by hand, and nobody can quietly forget.

The most important morning job is the leak probe, at 06:40 UK time. A leak is when data crosses a wall it should never cross, such as one breeder seeing another breeder's records, or a stranger reading something without signing in. A table is one list of records, like a single tab in a spreadsheet. The probe asks each live table for data while signed out, and checks what comes back. For private data the right answer is a refusal. If anything comes back that should not, the probe raises an incident, which is a recorded problem, dated and tagged to the app.

The leak probe has neighbours on the clock. At 06:10 UK time a stale check looks for tasks that have stopped moving. At 07:30 on weekdays a daily digest gathers what changed into one short summary for the owner. Every Monday at 05:20 a weekly backup runs, and the same job runs a change watch, which looks for changes on the platform the apps are built on. There is also a credit watch. Credits are the units the building platform charges for paid work, so the factory keeps a running eye on how many are being spent.

When an app goes live, it joins the weekly security check. That check covers three things for each app: its live links, its sign-in and its leak probe. A dead link, or a sign-in page that no longer works, is just as real a problem as a leak, because people cannot use the app. Each week the app also gets an export, which is a full copy of the app saved as a file, plus a backup of its records. The link to the backup folder is written on the app's card, so a restore never starts with a search.

Some checks run once a month. The app's KPIs, short for key performance indicators, are compared with the targets set for it. A KPI is simply a number you agreed to watch, such as how many breeders signed in this month. There is also a quieter job called new parts back to bricks, which is rule R14. If building the app created a useful new part, that part goes back into the brick registry, the factory's list of reusable parts. The next app can then start from it, instead of building the same thing twice.

Notice who does the watching. Scripts and AI helpers run the probes, the backups and the counts, and they record every result so it can be proved later. They never change who can see what. That decision stays with a person. One more weekly job is marked PROPOSED, which means it has been suggested but is not switched on yet: a weekly boost proposal, an idea for one small change to help people find the app. So the lap is watched by machines and steered by people.
