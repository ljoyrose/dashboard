## M07-L1 · How Build Prompts Are Written
**Outcome:** You can list what every paid build prompt must carry and explain why each prompt does only one job.  
**Length:** 758 words · about 5.8 min · Today

**Opener (Epiphany Bridge (light)):** Backstory: Rory, 13, watched his dad plan a Trimtable change for The Tidy Paw. · Desire: He wanted to ask for appointment reminders and a new price list in one request to save time. · Wall: If a two-job request goes wrong, nobody can tell which half broke or how to undo just that half. · Epiphany: One prompt, one job, one test and one way back.

| # | On Screen | Narration |
|---|---|---|
| 1 | One Request, Two Jobs, Big Risk | Rory is thirteen. He was watching his dad plan a change to Trimtable for Juno Platt's salon, The Tidy Paw. Rory had an idea to save time: ask the AI builder to add appointment reminders and a new price list in one request. One message, two jobs, done. His dad shook his head. In this stage every request costs credits, he said, and if a two-job request goes wrong, nobody can tell which half broke, or how to undo just that half. That was the moment it made sense. One prompt, one job, one test, one way back. |
| 2 | Stage 6 Is The Only Paid Stage | This is Stage 6, called Prompts. It happens in the room called Reactor, and it is the only paid stage in the whole factory. Every earlier stage is free planning and free building by hand. Here, the factory sends written instructions, called prompts, to the build platform's AI builder, and each answer, called a turn, spends credits. Because money is spent, the rules get stricter. Every prompt is prepared, checked and tested on paper first, and the factory owner gives the go word before each one is sent. Nothing is sent on a hunch. |
| 3 | One Goal, One Surface | The first rule is one goal, one surface. A surface is one part of the app that a person sees or uses, such as the booking screen or the price list. The template line puts it simply: an and means two prompts. Add reminders and change prices is two prompts, not one. Keeping prompts small means a failure is easy to spot and cheap to undo. There is a second split too. Tables and code never go in the same prompt. Tables are made by hand, for free, and the prompt is told not to change them. |
| 4 | The Blocks Every Prompt Carries | Every prompt is built from fixed blocks. A context block lists exactly which files the builder may read, and nothing else. A tables block says the tables were made by hand and must not be changed. And for any app with more than one brand, a walls block goes into every prompt for the life of the app. It states the app's classification, how a row belongs to a tenant, that the app must fail closed, and one line: if a change would weaken this, stop. Fail closed means that when in doubt, the app refuses access. |
| 5 | Each Prompt Carries Its Own Test | Each prompt also carries its own test. Where the app has brands, the test covers both walls: the brand wall, where Brand B cannot see Brand A, and the member wall, where one member cannot see another member's rows. The tests are run from outside the app by the factory's agents. The builder is never asked to build test panels or check its own work inside its turn. That would be a bit like marking your own homework. An outside test, run by someone else after the turn, is the only result that counts. |
| 6 | A Rollback Step For Every Prompt | Each paid prompt also carries a written rollback step. Rollback means going back to the last good version if a turn goes wrong. Before sending, the factory takes an export ZIP, a packed copy of every file in the app, so there is always a known good point to return to. Every prompt ends with one fixed line asking the builder, before building, to list anywhere else in the app that must change, and anything this could break. The builder reports that list first. Surprises found before building are cheap. Surprises found after building are expensive. |
| 7 | The Go Word And The Sends List | Before any prompt goes out, the factory writes a three-line pre-send report and adds a task to a list called Sends. Each send moves through fixed steps: draft, check, tested, the go word, sent, and verified live. The go word is a short command the factory owner types to approve one paid send. No agent can give it. Small wording or colour changes skip all of this. They go through the free visual editor instead, never through a paid prompt. Paying credits to change one word would simply be waste. |
| 8 | Small, Tested And Reversible | So a good build prompt is small, tested and reversible. It does one job on one surface. It carries the context block, the tables block and, for any app with brands, the walls block. It brings its own outside test for both walls, a rollback step and the what could this break question. It goes out only after the pre-send report and the owner's go word. Rory's two-job request becomes two careful prompts, each easy to check and easy to undo. Next lesson: what happens the moment a paid turn comes back. |

**Recap**
- One Goal, One Surface: An And Means Two
- Walls Block, Test And Rollback In Every Prompt
- Owner Gives The Go Word Before Each Paid Send
- Why it matters: Small Prompts Fail Small And Undo Easily

**Quiz**
1. Why is Stage 6 different from every other stage? A) It is the only stage with a gate · B) It is the only stage that uses tables · C) It is the only stage run by the customer · D) It is the only stage that spends credits · **Answer D**: Stage 6 is the only paid stage; every turn of the AI builder spends credits.
2. What does the rule 'an and means two prompts' mean? A) A request with two jobs is split into two prompts · B) Every prompt must be sent twice · C) Two people must write each prompt · D) Each prompt must name two brands · **Answer A**: One goal, one surface: if a request needs the word and, it becomes two separate prompts.
3. What does fail closed mean in the walls block? A) The app shuts down at night · B) Failed prompts are deleted · C) When in doubt, the app refuses access · D) The builder closes every file it opens · **Answer C**: Failing closed means the safe answer, no access, is the default whenever the app is unsure.
4. Who runs the tests a prompt carries? A) The AI builder, inside its own turn · B) The factory's agents, from outside the app, after the turn · C) The first real customer · D) Nobody, the builder's screen is enough · **Answer B**: Acceptance tests are run from outside; the builder never builds test panels or checks itself inside its turn.

## M07-L2 · After Every Paid Turn
**Outcome:** You can put the six after-turn steps in order and explain what the Send gate needs before an app moves on.  
**Length:** 734 words · about 5.6 min · Today

**Opener (Epiphany Bridge (light)):** Backstory: Ava, 15, watched a Litterline build turn finish, and the builder's screen said done. · Desire: She wanted to tell Mara Quill straight away that the new litter page was ready. · Wall: When she tested it as a brand-new member on the live site, the old page was still showing. · Epiphany: Done on the builder's screen is not done; proved live from outside is done.

| # | On Screen | Narration |
|---|---|---|
| 1 | Done On Screen Is Not Done | Ava is fifteen. She watched a Litterline build turn finish. The builder's screen said the new litter page was done, and Ava wanted to message Mara Quill, the breeder waiting for it, straight away. Her mum asked her to wait and run one test first, as a brand-new test member, on the live site. The old page was still showing. The new code had not reached the live app yet. Nothing was broken, but nothing was proved either. Done on the builder's screen is not done. Proved live, from outside, is done. |
| 2 | Six Steps, Always In This Order | After every paid turn, the factory follows six steps, always in the same order. One: record the turn. Two: check the spend and look for a refund. Three: publish. Four: re-probe every table. Five: run the member tests. Six: mark the send as done. The order matters. Recording comes first, so nothing is lost if something else goes wrong. Testing comes after publishing, so the tests run on the live app and not on an old copy. The engine refuses to close a send that is missing the record lines. |
| 3 | Step One: Record On Landing | Step one is record on landing, and it happens before any check, test or reply. The prompt exactly as sent, and the builder's reply, are written down word for word, with the credits and the time. The credit balance is noted on either side of the spend. Cancelled and failed turns are recorded too, because a failure is evidence. Why so strict? Memory is unreliable, and a turn that is not written down cannot be learned from or checked later. Every prompt and its full reply are kept in one file per app. |
| 4 | Step Two: Spend And Refund Check | Step two compares what the turn cost with the written estimate. If it cost more than one and a half times the estimate, the factory stops. It also looks for any charge with no prompt behind it, and for errors on the platform's side that burnt credits. Then it takes a fresh export ZIP and compares the files the prompt named against the last copy. If a named file did not change at all, the turn failed. The rule is to raise a refund ticket, not to send the same prompt again blind. |
| 5 | Steps Three And Four: Publish, Then Probe | Step three is publish, which puts the new version on the live site. Before testing, the factory checks that the live site really serves the new code, with the cache defeated. A cache is a saved copy a browser or server keeps so pages load faster, and it can show the old version, just as Ava saw. Step four re-probes every table anonymously. Anonymously means signed out, as a stranger. Every table should refuse a stranger unless it is meant to be public. This anonymous sweep runs after every publish, every time. |
| 6 | Step Five: Member Tests On Both Brands | Step five is the member tests. After every paid turn, an existing member and a brand-new member of each brand do the app's core action from start to finish. For Litterline, that could mean a breeder adding a litter record. Only the test identities from the register are used, never anyone's own account. After any turn that touched tables or security, the full test matrix runs too: every table, for a signed-out visitor, a Brand A member, a Brand B member and the owner. If a leak appears, the build stops. |
| 7 | The Send Gate (6-7): Proved Live | Step six marks the send as done, and a scorecard is written: what was predicted against what actually happened. Any gap becomes an action, such as a new checklist line, not just a note. When every planned prompt has been sent and checked, the app reaches the Send gate, from 6 to 7. Its rule is proved live, two fresh sign-ins. Fresh means a new sign-in, not a session left open from earlier. The factory owner decides at this gate. If the answer is yes, the app moves on to Launch. |
| 8 | Done Means Proved Live | So here is the lesson in one line: done means proved live from outside. After every paid turn the factory records, checks the spend, publishes, probes every table, runs member tests, and only then closes the send. If a leak was found and fixed, the same turn changes the app's card from Ly to Ln, so the record matches the truth. Ava learned to wait for one test before sending good news. The factory does that on every single turn. Next, the app gets its sales page, its domain and its funnels. |

**Recap**
- Record First, Before Any Check Or Reply
- Publish, Then Probe Every Table Signed Out
- Send Gate Needs Proof Live And Two Fresh Sign-Ins
- Why it matters: A Turn Is Only Done When Proved Live

**Quiz**
1. What is the first step after every paid turn? A) Publish the new version · B) Record the prompt and reply word for word · C) Run the member tests · D) Tell the customer it is ready · **Answer B**: Record on landing comes before any check, test or reply, so nothing is lost.
2. A file the prompt named did not change after the turn. What does the rule say? A) Send the same prompt again at once · B) Ignore it if the screen looks fine · C) Change the file by hand and move on · D) The turn failed, so raise a refund ticket and do not resend blind · **Answer D**: A named file with no change means the turn failed; the factory raises a refund ticket instead of re-prompting blind.
3. Why does the factory check the live code before testing? A) A cache can still be showing the old version · B) The builder asks it to · C) Live code is cheaper to test · D) Testing before publishing is not allowed by law · **Answer A**: A cache keeps saved copies, so tests must confirm the new code is really being served first.
4. What does the Send gate need before the app moves to Launch? A) A finished sales page · B) A full month of real users · C) Proved live, with two fresh sign-ins · D) A new domain name · **Answer C**: The Send gate rule is proved live, two fresh sign-ins, and the factory owner decides.
