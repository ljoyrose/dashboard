# After Every Paid Turn
M07 · Stage 6 · Prompts · Lesson 2 · about 6 min · 23 Oct 2026

**Video slot:** provider `rosequest` · id `TO CONFIRM` · type `v` · key `M07-L2`

**You can:** You can put the six after-turn steps in order and explain what the Send gate needs before an app moves on.

Ava is fifteen. She watched a Litterline build turn finish. The builder's screen said the new litter page was done, and Ava wanted to message Mara Quill, the breeder waiting for it, straight away. Her mum asked her to wait and run one test first, as a brand-new test member, on the live site. The old page was still showing. The new code had not reached the live app yet. Nothing was broken, but nothing was proved either. Done on the builder's screen is not done. Proved live, from outside, is done.

After every paid turn, the factory follows six steps, always in the same order. One: record the turn. Two: check the spend and look for a refund. Three: publish. Four: re-probe every table. Five: run the member tests. Six: mark the send as done. The order matters. Recording comes first, so nothing is lost if something else goes wrong. Testing comes after publishing, so the tests run on the live app and not on an old copy. The engine refuses to close a send that is missing the record lines.

Step one is record on landing, and it happens before any check, test or reply. The prompt exactly as sent, and the builder's reply, are written down word for word, with the credits and the time. The credit balance is noted on either side of the spend. Cancelled and failed turns are recorded too, because a failure is evidence. Why so strict? Memory is unreliable, and a turn that is not written down cannot be learned from or checked later. Every prompt and its full reply are kept in one file per app.

Step two compares what the turn cost with the written estimate. If it cost more than one and a half times the estimate, the factory stops. It also looks for any charge with no prompt behind it, and for errors on the platform's side that burnt credits. Then it takes a fresh export ZIP and compares the files the prompt named against the last copy. If a named file did not change at all, the turn failed. The rule is to raise a refund ticket, not to send the same prompt again blind.

Step three is publish, which puts the new version on the live site. Before testing, the factory checks that the live site really serves the new code, with the cache defeated. A cache is a saved copy a browser or server keeps so pages load faster, and it can show the old version, just as Ava saw. Step four re-probes every table anonymously. Anonymously means signed out, as a stranger. Every table should refuse a stranger unless it is meant to be public. This anonymous sweep runs after every publish, every time.

Step five is the member tests. After every paid turn, an existing member and a brand-new member of each brand do the app's core action from start to finish. For Litterline, that could mean a breeder adding a litter record. Only the test identities from the register are used, never anyone's own account. After any turn that touched tables or security, the full test matrix runs too: every table, for a signed-out visitor, a Brand A member, a Brand B member and the owner. If a leak appears, the build stops.

Step six marks the send as done, and a scorecard is written: what was predicted against what actually happened. Any gap becomes an action, such as a new checklist line, not just a note. When every planned prompt has been sent and checked, the app reaches the Send gate, from 6 to 7. Its rule is proved live, two fresh sign-ins. Fresh means a new sign-in, not a session left open from earlier. The factory owner decides at this gate. If the answer is yes, the app moves on to Launch.

So here is the lesson in one line: done means proved live from outside. After every paid turn the factory records, checks the spend, publishes, probes every table, runs member tests, and only then closes the send. If a leak was found and fixed, the same turn changes the app's card from Ly to Ln, so the record matches the truth. Ava learned to wait for one test before sending good news. The factory does that on every single turn. Next, the app gets its sales page, its domain and its funnels.

## Recap
- Record First, Before Any Check Or Reply
- Publish, Then Probe Every Table Signed Out
- Send Gate Needs Proof Live And Two Fresh Sign-Ins
- **Why It Matters:** A Turn Is Only Done When Proved Live

## Quiz
1. What is the first step after every paid turn?
   - A) Publish the new version
   - B) Record the prompt and reply word for word
   - C) Run the member tests
   - D) Tell the customer it is ready
   - Answer: B. Record on landing comes before any check, test or reply, so nothing is lost.
2. A file the prompt named did not change after the turn. What does the rule say?
   - A) Send the same prompt again at once
   - B) Ignore it if the screen looks fine
   - C) Change the file by hand and move on
   - D) The turn failed, so raise a refund ticket and do not resend blind
   - Answer: D. A named file with no change means the turn failed; the factory raises a refund ticket instead of re-prompting blind.
3. Why does the factory check the live code before testing?
   - A) A cache can still be showing the old version
   - B) The builder asks it to
   - C) Live code is cheaper to test
   - D) Testing before publishing is not allowed by law
   - Answer: A. A cache keeps saved copies, so tests must confirm the new code is really being served first.
4. What does the Send gate need before the app moves to Launch?
   - A) A finished sales page
   - B) A full month of real users
   - C) Proved live, with two fresh sign-ins
   - D) A new domain name
   - Answer: C. The Send gate rule is proved live, two fresh sign-ins, and the factory owner decides.
